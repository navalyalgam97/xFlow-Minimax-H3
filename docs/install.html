ComfyUI Custom Node · v1.13.0

xFlowOne · Minimax H3 — installation guide

A single-node video interface for MiniMax H3 in ComfyUI: text-to-video, image-to-video, and reference-image + audio lip-sync, all inside one 16:9 node. This guide installs it from the ZIP file you were given — upload, unzip, restart. Covers RunPod, Vast.ai, and a local PC.

T2V I2V · first + last frame R2V · speak / sing Built-in model downloader Gallery + fullscreen Up to 9 reference images No extra Python packages

1 What this node is

One node, three generation modes, no graph to wire up.

🎬 T2V — Text to Video

Prompt in, clip out. Orientation and size dropdowns, 1–10 s duration slider with live frame count, 24/30 fps.

🖼 I2V — Image to Video

Start frame, plus an optional end frame. Uploading both automatically switches to the first-frame/last-frame workflow.

🎙 R2V — Reference + Audio

Reference image + audio track, routed to SPEAK (lip-sync) or SING. Optional second reference image and reference video.

Everything else lives on the node face: an audio waveform cropper, a LoRA stacker, a gallery of your renders with in-node playback and download, a generation timer and stop button, an inline Help drawer, and a Setup panel that downloads the model weights for you with live progress.

2 Before you start

Two minutes of prep that prevents the three most common install failures.

  • A working ComfyUI install you can already open in a browser.
  • Python 3.9+ with the usual ComfyUI dependencies. This node installs no extra packages — it only uses aiohttp and folder_paths, which ComfyUI already ships.
  • The MiniMax H3 nodes must exist in your ComfyUI build (the Pixaroma / Comfy-Org H3 nodes such as MiniMaxH3ReferenceToVideo and PixaromaLoadImageMini). This node builds and submits those graphs for you; it does not reimplement them.
  • Roughly 60 GB of free disk for the model weights (section 5). The node package itself is under 1 MB.
Find your ComfyUI folder first. The terminal where ComfyUI starts prints its base path on launch. Everything below is relative to that folder — the one containing main.py, models/, output/ and custom_nodes/.

The one structure that must be right

After unzipping, __init__.py must sit directly inside the node folder, one level under custom_nodes/. A ZIP often contains a single wrapper folder, and unzipping carelessly leaves you with that folder twice — the most common reason the node never shows up.

✓ Correct

ComfyUI/custom_nodes/
└── xFlow-Minimax-H3/
    ├── __init__.py          ← right here
    ├── nodes.py
    ├── minimax_h3_video_nodes.py
    ├── config.json
    ├── web/
    │   └── minimax_h3_video.js
    └── workflows/
        ├── text_to_video_workflow.json
        ├── image_to_video_workflow.json
        ├── image_to_video_fflf_workflow.json
        ├── reference_to_video_workflow.json
        └── reference_to_video_sing_workflow.json

✗ Wrong — one level too deep

ComfyUI/custom_nodes/
└── xFlow-Minimax-H3/
    └── xFlow-Minimax-H3/    ← ComfyUI
        ├── __init__.py         never
        └── web/                looks here

Fix: move the inner folder up one level and delete the empty outer one. The folder name itself does not matter — only the depth of __init__.py.

4 Upload and unzip

Pick the route that matches where ComfyUI is running.

On a cloud GPU box, upload the ZIP as-is — do not unzip it on your own PC first. One file uploads in seconds; the same content as ~40 loose files through a browser file manager is slow and frequently drops files halfway.

Route A RunPod — JupyterLab

  1. Open JupyterLab from the pod: Connect → Connect to JupyterLab [Port 8888].
  2. Navigate to the destination in the left-hand file tree: workspace → ComfyUI → custom_nodes. Check the breadcrumb above the file list reads / workspace / ComfyUI / custom_nodes before uploading — this is what puts the ZIP in the right place.
  3. Upload the ZIP. Click the ⬆ upload arrow in the file-browser toolbar and choose the file, or drag it from your desktop straight onto the file list. Wait for the progress bar to reach 100% and the file to appear in the list.
  4. Open a terminal: File → New → Terminal.
  5. Run the unzip block below. It unzips into a temp folder, shows you what is inside, then puts the real folder in place.
  6. Restart ComfyUI — section 6.
# 1 — go to the destination and confirm the ZIP is here
cd /workspace/ComfyUI/custom_nodes
ls *.zip

# 2 — if 'unzip: command not found', install it (skip otherwise)
apt-get update && apt-get install -y unzip

# 3 — unzip into a temp folder and look inside
unzip -o xFlow-Minimax-H3.zip -d _xflow_tmp
ls _xflow_tmp

Step 3 prints one of two things. Follow the matching block:

Case 1 — files, no wrapper

ls showed __init__.py, web, workflows …

mv _xflow_tmp xFlow-Minimax-H3

Case 2 — a single folder

ls showed one folder name and nothing else.

mv _xflow_tmp/*/ xFlow-Minimax-H3
rmdir _xflow_tmp

Then verify and clean up — the first command must print the path, not an error:

ls /workspace/ComfyUI/custom_nodes/xFlow-Minimax-H3/__init__.py
rm -f /workspace/ComfyUI/custom_nodes/*.zip
rm -rf /workspace/ComfyUI/custom_nodes/__MACOSX
Uploaded the ZIP to the wrong folder? No need to re-upload — move it. From a terminal: 
find / -name "xFlow-Minimax-H3*.zip" -not -path "*/proc/*" 2>/dev/null
mv /workspace/xFlow-Minimax-H3.zip /workspace/ComfyUI/custom_nodes/

Route B Vast.ai — Jupyter or instance portal

Same procedure as Route A, with one difference: confirm the path first. Vast.ai templates vary — most ComfyUI images use /workspace/ComfyUI, AI-Dock-based images use /opt/ComfyUI. Run the ls -d check from section 3, then use whichever path it prints in the commands above.

If your instance gives you a Jupyter Upload button but no terminal, upload the ZIP into custom_nodes and unzip from a notebook cell instead. This handles the wrapper folder automatically:

# paste into a Jupyter notebook cell and run
import os, glob, shutil

base = "/workspace/ComfyUI/custom_nodes"        # adjust if your path differs
zips = glob.glob(os.path.join(base, "*.zip"))
print("found:", zips)

tmp = os.path.join(base, "_xflow_tmp")
shutil.unpack_archive(zips[0], tmp)

# find the folder that actually holds __init__.py, wrapper or not
src = tmp
for root, dirs, files in os.walk(tmp):
    if "__init__.py" in files:
        src = root
        break

dst = os.path.join(base, "xFlow-Minimax-H3")
if os.path.isdir(dst):
    shutil.rmtree(dst)                          # replaces an older copy
shutil.move(src, dst)
shutil.rmtree(tmp, ignore_errors=True)
os.remove(zips[0])

print("installed to:", dst)
print(sorted(os.listdir(dst)))                  # must list __init__.py, web, workflows

Route C Local PC — Windows, macOS, Linux

No terminal needed here at all.

  1. Extract the ZIP.
    • Windows: right-click the ZIP → Extract All… → Extract. Do not drag files out of the ZIP preview window — Windows shows an unopened archive like a normal folder, and copying from it can silently skip files.
    • macOS: double-click the ZIP. Ignore any __MACOSX folder that appears.
    • Linux: right-click → Extract Here.
  2. Open the extracted folder and find __init__.py. If you instead see a single folder with the same name, open it — that inner folder is the one to install.
  3. Copy that folder into your ComfyUI\custom_nodes\ directory (paths in section 3). Copy the whole folder, not its contents.
  4. Check the result: custom_nodes\xFlow-Minimax-H3\__init__.py must exist. Rename the folder to anything you like — only the depth matters.
  5. Restart ComfyUI — section 6.
Windows: extract before you copy. Copying straight out of a ZIP preview is the single most common cause of a half-installed node on Windows — the folder looks right, but web/ or workflows/ comes across empty and the node loads as a blank grey box.

5 Get the model weights

The package ships no weights. Let the Setup panel fetch them, or place them yourself.

The easy way: start ComfyUI, add the node, and open the ⚙ Setup drawer on the node face. Each model gets a card with a download button, live MB/s, pause / resume / delete, and its source link. Files land in the correct folders automatically. Use this on RunPod and Vast.ai — the download runs at datacentre speed instead of over your home connection.

The manual way: download the files and place each one in the folder below, relative to your ComfyUI root.

FileGoes inNeeded for
minimax_h3_fl2va_pruned_int8_convrot.safetensors models/diffusion_models/h3/T2V, I2V
minimax_h3_ref2va_pruned_int8_convrot.safetensors models/diffusion_models/h3/R2V
qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors models/text_encoders/all modes
minimax_h3_video_vae_fp16.safetensors models/vae/all modes
minimax_h3_audio_vae_fp32.safetensors models/vae/R2V audio

All five come from huggingface.co/Comfy-Org/MiniMax-H3. The h3/ subfolder under diffusion_models/ matters — the workflows reference the models by that path.

Cloud pods: keep the weights on the persistent volume. On RunPod, only /workspace survives a pod stop — anything downloaded into the container image is gone on restart, and you pay to pull ~60 GB again. If ComfyUI lives outside /workspace, store the models on the volume and point ComfyUI at them with an extra_model_paths.yaml instead of copying them in.

6 Restart and verify

Two checks: one in the server log, one in the browser.

  1. Fully restart ComfyUI. A browser refresh is not enough — the Python process must reload to pick up a new custom node. On RunPod / Vast.ai, stop and start the ComfyUI process, or restart the instance.
  2. Watch the startup log for this line. If it is missing, the folder depth is wrong (section 3) or a Python error is printed just above it: 
    [MinimaxH3Video] Backend node loaded successfully.
  3. Hard-refresh the browser tab — Ctrl+Shift+R, or Cmd+Shift+R on macOS. The node's interface is a JavaScript file served from web/, and a cached older copy is why a node sometimes renders as a blank grey box.
  4. Add the node: double-click empty canvas and type Minimax H3 One-Node Video, or right-click → Add Node → Minimax H3 → Minimax H3 One-Node Video.
  5. Generate something. Stay in T2V, type a prompt, press Generate. The timer counts up under the preview; the clip plays inside the node when it lands, and is written to ComfyUI/output/MinimaxH3/ when Auto-save is on.

7 When it does not work

Symptom → cause → fix. Every one of these has been seen in the wild.

The node does not appear in the search menu

Almost always the folder-depth problem. Confirm custom_nodes/<folder>/__init__.py exists exactly one level deep. Then read the startup log above where the success line should be — an import error there names the real cause.

The node appears but is a blank / grey box

The frontend file did not load. Hard-refresh (Ctrl+Shift+R), then open DevTools (F12) → Console and Network and look for a 404 on minimax_h3_video.js. A 404 means web/ did not survive the copy — re-extract and re-upload.

"no usable sound file selected"

Make sure you are on 1.11.2 or later. Earlier workflow templates carried sample filenames that only resolve on a machine holding those demo assets.

A run fails right after moving to a cloud box

Uploaded filenames persist in the node, but the files themselves live in ComfyUI/input/ — a different machine does not have them. From 1.11.1, missing optional inputs are pruned with a console warning instead of killing the run; a missing required image still has to be re-uploaded through the node.

Model errors, or an obviously wrong-looking result

Check the five filenames against the table in section 5, including the h3/ subfolder. From 1.8.0 the node refuses to substitute a different model when a name does not resolve — you get a clear error naming the missing file rather than a plausible-but-wrong video.

Reference image or audio seems ignored

A real defect in 1.7.0 and earlier: R2V and I2V silently ran the text-to-video workflow. Fixed in 1.8.0 — on an older copy, nothing else will fix it. The installed version is shown in the bottom-right of the Help drawer.

Still stuck? Have the ComfyUI startup log and the browser console output ready — those two together identify nearly every install problem on sight. Support: Discord.

8 Updating and removing

One folder in, one folder out. Nothing else in ComfyUI is touched.

Update to a newer version

Delete the old folder first, then install the new ZIP exactly as above. Do not extract on top of an existing install — a leftover file from an older version can shadow a new one and produce failures that make no sense. Nothing you care about lives in this folder: renders stay in ComfyUI/output/MinimaxH3/ and weights stay in ComfyUI/models/, so both survive the swap.

Remove it

Delete ComfyUI/custom_nodes/xFlow-Minimax-H3/ and restart ComfyUI. Your generated videos and the model weights are untouched — delete those separately if you want the disk space back.
